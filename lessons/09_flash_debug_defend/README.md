# Lesson 09: Flash, Diagnose, and Defend

## Where We Are

The final lesson treats flashing as a protocol with evidence, not a magic button.
OpenOCD talks to the ST-Link over USB; the probe talks SWD to the Cortex-M3 debug
port; the target flash driver erases, programs, reads back, and verifies bytes.

## Final Contract

The project must:

- compile without warnings or host/runtime libraries;
- place a valid vector table at the flash origin;
- stay within the declared 64 KiB flash and 20 KiB SRAM contract;
- program and report `Verified OK`;
- software-reset without requiring an NRST wire;
- blink PC13 continuously with `BOOT0` set to zero.

## Assignment

1. Run all final checks and explain every line they validate.
2. Flash and save the important probe, target-voltage, device-ID, programming,
   verification, and reset observations in `notes/final.md`.
3. Answer the defence questions below without looking at `solutions/`.
4. Only after that, compare your files with `solutions/final/`.

## Defence Questions

1. What happens from reset until the first statement in `main`?
2. Why must GPIOC be clocked before its configuration register is useful?
3. How are the four PC13 configuration bits derived?
4. Why is the board LED active-low?
5. Why are peripheral accesses `volatile`?
6. Which parts were written by you, supplied as plumbing, and generated by tools?
7. What would you replace first to obtain accurate, non-blocking timing?
